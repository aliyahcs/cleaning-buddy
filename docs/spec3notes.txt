Cleaning Buddy Data Modeling Narrative and Business Rules
Overview:
The Cleaning Buddy application is designed to help users manage and maintain household
cleaning tasks through structured scheduling, reminders, and performance tracking. The data
model supports a single-user system where each user configures their cleaning preferences,
completes a one-time quiz, selects a weekly cleaning day, and tracks progress through room-
based task completion.
The database is designed using a relational model to ensure data integrity, reduce redundancy,
and support scalability for features such as analytics, notifications, and progress tracking.
The data model was designed with the following goals:
1. Support onboarding and personalization
o One-time cleanliness quiz
o Dwelling type selection
o Top two room priorities
2. Enable structured task management
o Predefined room-based cleaning tasks
o Checklist-based workflow (no custom tasks)
3. Support scheduling constraints
o One weekly cleaning day
o Limited postponement options (tomorrow or next week)
4. Track progress and performance
o Room completion logic (all tasks must be complete)
o Weekly cleanliness health score (0–100%)
5. Provide notifications and insights
o Push and in-app notifications
o Cleaning tips and analytics


Core Entities and Their Roles
1. Users and Profiles
• Users represent individuals using the app.
• User_Profiles store configuration data collected during onboarding.
Each user:
• Has exactly one profile
• Selects a dwelling type
• Chooses one cleaning day
• Receives a neat freak score and category
This separation ensures authentication data is isolated from user preferences.
2. Cleaner Categories
The Cleaner_Categories entity defines the five classification levels:
• Minimalist Maintainer
• Casual Cleaner
• Routine Ready
• Neat Freak
• Spotless Specialist
Each category corresponds to a score range (0–100).
This allows:
• Consistent classification
• Reusable logic for messaging and analytics
3. Quiz System
The onboarding quiz is modeled using:
• Quiz_Questions
• Quiz_Answer_Options
• User_Quiz_Responses
This structure supports:
• A one-time quiz per user
• Scored answers for calculating the neat freak score
• Flexibility to modify questions without altering schema
Each user can only answer each question once, enforcing the “one-time quiz” requirement.
4. Dwelling and Room Structure
The app organizes cleaning by location:
• Dwelling_Types (apartment, studio, house)
• Rooms (kitchen, bathroom, bedroom, etc.)
• Dwelling_Type_Rooms (mapping table)
This allows:
• Different room configurations per dwelling type
• Scalability if new dwelling types are added
5. Task Templates
Cleaning tasks are predefined and stored in:
• Task_Templates
Each task:
• Belongs to a room
• Is reused across all users
This design enforces:
• Standardized cleaning checklists
• No custom task creation (as required)
6. User Priorities
The app allows users to select two priority rooms, stored in:
• User_Room_Priorities
Constraints:
• Only two priorities allowed
• Ranked as 1 (highest) and 2
These priorities influence:
• Scheduling
• Notifications
• Analytics
7. Scheduling and Cleaning Cycles
Cleaning is managed weekly using:
• Cleaning_Cycles
Each cycle represents:
• One week of cleaning
• One scheduled cleaning day
This ensures:
• Only one cleaning day per week
• Easy tracking of weekly performance
8. Room Checklists and Task Instances
To track progress:
• Cycle_Room_Checklists represent each room in a cycle
• Cycle_Tasks represent individual task instances
Important rule:
• A room is only complete if all tasks are complete
This structure allows:
• Accurate room-level completion tracking
• Task-level progress monitoring
9. Postponements ( May need to re-evaluate after this update )
Postponement behavior is restricted using:
• Task_Postponements
Constraints:
• Only two options:
o “Tomorrow”
o “Next week”
o Wants to be able to input a date
This ensures:
• Controlled scheduling
• Simplicity in logic / May change the logic due to date input, possible calendar pop-up
10. Notifications
The notification system includes:
• Notification_Sounds
• User_Notification_Preferences
• Notifications
Users can:
• Enable push or in-app reminders
• Select a notification sound
The system logs all notifications sent for tracking and debugging.
11. Weekly Health Scores
User performance is summarized in:
• Weekly_Health_Scores
This table calculates:
• Percentage of completed tasks/rooms
• Score between 0–100%
• Associated feedback message
Each cleaning cycle produces exactly one health score.
12. Sharing and Analytics
Additional support features include:
• Score_Shares
o Allows users to copy/share scores (no social media integration)
• Analytics_Snapshots
o Stores aggregated performance data
o Identifies problem areas (e.g., most missed room)
13. Cleaning Tips
• Cleaning_Tips provides static best practices such as:
o Clean top to bottom
o Dust before sweeping
This table supports:
• Simple content delivery
• Easy updates without code changes
Key Relationships and Cardinality
Some important relationships include:
• One user → one profile (1:1)
• One user → many cleaning cycles (1:M)
• One cycle → many rooms (1:M)
• One room → many tasks (1:M)
• One cycle → one health score (1:1)
These relationships enforce:
• Data consistency
• Logical flow of cleaning activities
Constraints and Business Rules
The data model enforces key application rules:
• Only one quiz attempt per user
• Only one cleaning day per week
• Only two priority rooms
• Only two postponement options
• Tasks must be completed to mark a room complete
• The app is single-user only (no shared households)
Normalization and Integrity
The schema is normalized to approximately Third Normal Form (3NF):
• No repeating groups
• No partial dependencies
• No transitive dependencies
Benefits:
• Reduced redundancy
• Improved consistency
• Easier maintenance
Conclusion
The Cleaning Buddy data model is designed to align closely with the app’s functional
requirements while maintaining a clean, scalable, and normalized structure. It supports the full
lifecycle of the user experience:
1. Onboarding → Quiz → Profile setup
2. Task generation → Scheduling → Notifications
3. Task completion → Room completion → Weekly scoring
4. Insights → Analytics → Sharing
This structure ensures that the application remains simple for users while being robust enough
to support future enhancements.
Navigation Plan:
The User enters the application by creating an account, with their first and last name and an
email address and password. During their first login, they have to take a Cleanliness Quiz that
will give them a cleaning title and score. Once they are given their cleaning title, then they pick
their dwelling type. After the dwelling type, them they prioritize their two rooms that are most
important to them. After prioritizing the rooms, then they are asked select a cleaning day and
time. Then they are asked to set up their notification time of when they should be reminded to
start cleaning on their cleaning day. Once that is completed then they are taken to the Cleaning
Buddy dashboard. Where they can see what there cleaning title is, their cleaning day and time,
what view they want to see(cleaning tasks or view the schedule), and at the bottom of the
screen there will be upcoming tasks to be completed. One you click on My tasks, you will get a
screen with all rooms in your dwelling type. Each room will have a box display that can be
clicked on to see what exactly needs to be completed in that room, with checkmark boxes to fill
in. Along with that there will be a weekly summary strip at the bottom of the screen, that will
give the user information on how many tasks they completed, how many tasks they had, the
percentage of tasks they completed, and how many rooms they totally completed. There will
be a quick add task at the top of the page if a task was left out of the list. Once you click on the
room you want to see, you will be given a screen with each that needs to be completed in that
room (along with buttons at the top of the screen that will move you from room to room in your
dwelling). Also on the list page or each room, you will have buttons to get back to the
dashboard, My Tasks, Checklists, Analytics, Tips, and Settings screens. Within the Tasks
Checklist you will have the opportunity to postpone a task, with today, next week, or enter a
date. On the Analytics screen, you have are given a weekly health score, how many weeks you
have been using the app, total number of tasks for the week, what percentage by room you
have completed, and monthly trends by week. You also have access to the other parts of the
app with buttons at the top of the screen. You get to the tips page by accessing the tipsbutton
at the top of the page, as well as, accessing your profile and notification settings by accessing
the settings button at the top of the page. You can also access the Help section using the button
at the top of the screen. That is how you navigate throughout the Cleaning Buddy app
